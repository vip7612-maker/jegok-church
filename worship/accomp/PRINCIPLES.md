# 제곡교회 주일예배 악보집 — 원칙 (교장님 확정, 2026-10-03)

예배자 악보집(옛 이름 반주자·싱어용 악보, 2026-10-03 이름 바꿈)을 구글 슬라이드 대신 HTML 로 만든다. 교장님이 텔레그램으로 말씀하시거나
악보 사진을 주시면 데이터를 고치고 다시 올린다. **아래 원칙은 매주 그대로 지킨다.**

## 1. 주소·기록
- 그 주 악보집: `https://report-site-kohl.vercel.app/jegok_worship_YYYYMMDD` (예: jegok_worship_20261004)
- 모음(계속 쌓임, 최신 주가 위): `https://report-site-kohl.vercel.app/jegok_worship`
- 노션 「📖 주일예배 악보집」 DB(제곡교회 예배팀 페이지 아래)에 같은 날짜 한 줄 — 예배일·설교본문·설교제목·인도자·곡 목록·링크
- 셋 다 `python3 accomp/build.py <날짜> --share` 한 번으로 갱신(publish.py). 고칠 때마다 같은 주소로 다시 올린다.
- 팀 이름은 **예배팀**(찬양팀 아님). 표지 오른쪽 아래 「제곡교회 예배팀」.

## 1-1. 예배 준비(「예배 준비하자」)
- prep.py 가 폴더 `YYYY MMDD 주일예배 <인도자>`(인도자는 섬김표에서) + 주일예배 PPT 를 만들고, 예배자 악보는 **구글 슬라이드 대신 HTML 악보집**을 연다(weekly.py): 지난주 바탕, 설교·악보·공지 비움, 섬김표 기본값 채움 → 게시 → 폴더에 `YYYY MMDD 예배자 악보.html`.
- 악보집을 고친 뒤 드라이브 파일도 갱신: `weekly.py <날짜> --upload`.

## 2. 쪽 순서
표지 → 섬김표 → 암송 → 암송 → 설교본문 → 설교요약 → 도입곡 → 사도신경 → 본곡 1·2·3…(두 곡씩) → 적용송(맨 끝)

## 3. 표지
- 남색 새벽빛 배경 + 금빛 빛줄기·십자가·흐르는 오선과 음표. 「주일예배」 크게, 「예배자 악보」, 날짜 + 「주일」.

## 4. 섬김표 (accomp/roster.json 하나로 관리 — 주보마다 따로 두지 않음)
- 그 주부터 **6주**를 한 표에. 이번 주 칸은 남색 머리 + 노란 바탕. 머리 오른쪽엔 기간만(「10.4 ~ 11.8」 — 「· 6주」 같은 글자 없음).
- 그룹 「인도·세션」(인도자·메인KB·세컨KB·드럼): 날짜마다 **두 칸을 합친 긴 칸 하나**, 한 줄.
- 「싱어」(단상·회중): 한 칸에 이름 자리 **4개(2×2)**, 「미디어」 방송실 4개, **촬영 2개(2×1)**. 빈 자리는 비워 두되 자리는 유지.
- 이름은 **두 글자든 세 글자든 같은 폭**, 글자 크기는 모든 그룹이 같다.
- 평소 편성(기본값): 인도자 이경진 · 메인KB 김은정 · 세컨KB 정다이 · 드럼 정상진. **매월 넷째 주일 드럼은 정영화**.
  기본값과 다른 사람은 **사람마다 다른 색 바탕 흰 글씨**(정영화 보라·정상진 청록, roster.json person_colors, 빨강 금지). 색 안내 문구는 넣지 않는다.
- 지원팀: 날짜와 상관없는 전체 명단. 미디어 바로 아래에 붙이고, 「지원팀 11명」 처럼 인원수를 같은 줄에 작게(안내 문구 없음).
- 맨 아래 **공지사항** 칸(테두리 + 옅은 음영): data/<날짜>.json 의 `notices`.
- 고치기: `roster.py set|add|rm <날짜> <역할> <이름>`, `copy`, `fill`(기본값·규칙 채우기), `support add|rm`.

## 6. 설교본문·설교요약
- 설교본문: 개역개정 그대로(bible_lookup.py), 절 번호 굵게. 글자는 칸에 맞춰 줄이되 **최대 18pt**.
- 설교요약: 왼쪽 위 **제목·본문 구절을 음영 상자**로 늘 구분(설교본문 쪽에서 자동으로 가져옴), 그 아래 요약 본문, 좌우 두 단.
- 사도신경: 교장님 본문 줄바꿈 그대로(creed.txt), 한 줄이 접히지 않게 화면 가득.

## 7. 악보
- 쪽 번호가 아니라 **곡 번호**로 부른다: 도입곡 / 1·2·3… / 적용송. 끼워 넣으면 뒤 번호가 밀린다.
- 번호표 + **곡 제목(작게)** 은 칸 맨 위 한 줄을 차지하고, 악보는 그 **제목 글씨 아래 선에서 시작**한다 — 악보 위에 겹쳐 얹지 않는다(2026-10-03 교장님 지시, 겹치면 원래 제목·작곡자가 가려짐). 위치 표시 「9쪽 왼쪽」 같은 글자는 없음.
- **악보 그림은 언제나 바깥 흰 여백을 타이트하게 잘라 붙인다** (2026-10-04 교장님 원칙 — 「감사와 찬양 드리며」 새 악보를 위 흰 부분째 붙였던 일).
  어떤 길로 들어오든 같다: 텔레그램·악보집(score.py trim)·콘티 편집판 붙여넣기·「➕ 올리기」·직접 교체·악보 DB.
  자르는 곳은 `accomp/trim.py` 하나(어두운 점이 0.3% 넘는 줄·열만 남기고 폭의 1.2% 여백) — build.py 가 악보집을 만들 때(img_src),
  conti_sync 가 편집판 그림을 가져올 때, uploads.py 가 올린 악보를 등록할 때 자동으로 거친다. 손으로 바꿀 때도 `python3 accomp/trim.py <파일>` 먼저.
- 곡이 홀수면 오른쪽 빈칸에 「다음 번호 자리」 — 화면에만 보이고 인쇄엔 안 나온다.
- 명령: `score.py add|set|rm|move|title|list|trim <날짜> …`

## 9. 악보 보관함 (2026-10-03 교장님 확정)
- 노션 「🎵 찬양 콘티」 한 DB 안에서 관리한다(악보 DB 를 따로 두지 않음). 곡마다 **곡번호**, 악보는 **코드별**로 한 장씩 **악보번호**(악보-0001…).
- 곡 페이지: 「악보」 칸에 `[G] 악보-0007 곡명.jpg` 식으로 코드별 파일, 「악보 코드」 칸, 본문에 코드별 제목+출처+쓴 날+그림.
- 같은 곡·같은 코드로 다시 넣으면 그 코드 악보를 바꾼다(번호 유지). 다른 코드면 새 악보번호.
- 악보를 넣을 때는 늘 `--key` 를 붙여 보관함에도 쌓는다. 사진 없이 「보관함」으로 꺼내 쓸 수 있다. 원본은 accomp/bank/, 기록은 score_bank.json.
- 결석(2026-10-03): `roster.py absent 10.4 이름` — 섬김표에서 이름은 그대로 두고 흐리게(회색·옅게). 되돌림 `absent rm 10.4 이름`.
- 곡 제목 유튜브(2026-10-03): 악보 위 번호 옆 곡 제목에 유튜브 하이퍼링크(▶). data 의 youtube, 없으면 보관함(score_bank.json) youtube. 넣을 땐 `score.py … --youtube URL`. 유튜브 주소는 music.py search 로 공식·대표 영상.
- PPT(2026-10-03): 「PPT」 단추 → 같은 폴더 ppt.html — 쪽마다 한 장(A4 가로) 보기 + [PPT 내려받기] doc.pptx. build.py --share 때 pptpage.py 가 자동으로 만든다.
- 주보(2026-10-03): 「주보」 단추 → jubo.html = 그 주 드라이브 「…주보.hwp」를 kordoc 으로 읽어 휴대폰용 HTML 로 다시 짠 주보(jubo_html.py — 머리·예배순서·오늘의 말씀·샘터모임·표·교회소식). 위쪽 [⬇ 주보 PDF]로 원본 PDF. 한글 파일이 없으면 PDF 쪽 그림 보기, 둘 다 없으면 「아직 올라오지 않았습니다」. 주보가 폴더에 올라오면 build --share 다시.
- 예배 화면 PPT(2026-10-03): 「PPT」 단추는 *예배 시간 앞 화면용 주일예배 PPT* 를 보여 준다. PPT 를 PDF 로 바꾼 파일을 accomp/worship_ppt/<날짜>.pdf(원본 .pptx 도 같은 이름) 에 두고 build --share → slides.py 가 장마다 배경 그림 + 보이는 글자만 HTML 로 다시 짠다(가려진 곡 구간 표시는 뺌). 목록 보기·▶ 발표(전체 화면·방향키·밀기)·순서 바로가기(성경암송·찬양 곡 이름·설교…)·원본 PDF/PPT 내려받기. 곡 이름은 그 주 악보집 순서에서. 파일이 없으면 악보집 쪽 그림 PPT(pptpage.py).
- 곡 코드(2026-10-03 교장님 지시): 악보 위 번호 옆, 제목 앞에 코드를 적는다 — 「5 G 온 땅의 주인」. 코드는 data 의 key(악보를 `--key` 로 넣으면 저절로), 없으면 보관함 기록(그 곡 악보가 한 장뿐이거나 이번 주에 쓴 코드). `score.py key <날짜> 5 G`.
- 한 곡 두 코드(2026-10-03): 「5 G→A 온 땅의 주인」 — G 를 누르면 G 코드 악보, A 를 누르면 A 코드 악보가 그 자리에 보인다(발표 화면도 같음). `score.py key <날짜> 5 G A` → 보관함의 G·A 악보를 data 의 keys 로 이어 붙인다(두 코드 악보가 보관함에 먼저 있어야 함).
- PPT 화면(2026-10-03 교장님 지시): 기본은 한 장씩 보기 — 왼쪽 목차를 누르면 스크롤 없이 오른쪽에 그 장만 바로 뜬다. ◀ 이전·다음 ▶·방향키·밀기로 넘김. 위 「☰ 목록으로 보기」로 예전처럼 쭉 내려 보기도 된다.
- PPT ▶ 발표 = 두 모니터(2026-10-03 교장님 지시): 메인 모니터는 발표자 보기(지금 장·다음 장·장 번호·경과 시간·이전/다음·목차로 이동), 두 번째 모니터에 앞 화면 창(ppt.html?screen=1). 두 창은 BroadcastChannel 로 장을 맞춘다. 크롬 창 관리 권한으로 두 번째 모니터를 찾아 띄우고, 모니터가 하나면 예전처럼 그 창에서 전체 화면.
- 예배 PPT 자동(2026-10-03 교장님 지시): build --share 때 그 주 드라이브 폴더의 「…주일예배 PPT」(.pptx)를 받아 worship_ppt/<날짜>.pptx·.pdf 로 두고(PDF 는 구글 슬라이드 임시 변환 후 지움, slides.py fetch) PPT 단추는 늘 예배 PPT 를 보여 준다. 드라이브에 없을 때만 악보집 쪽 그림 PPT.
- 발표자 보기 아래(2026-10-03 교장님 지시): 지금 노래(순서)의 모든 장을 썸네일로 — 누르면 앞 화면(듀얼 모니터)도 그 장으로. 노래 구간은 왼쪽 목차 표시 사이.

## 10. 예배 PPT 성경 봉독 (2026-10-04 교장님 원칙)
